Four open math challenges

Pick one, try it in the browser, and see whether you can find a strategy, a proof or a counterexample. Some answers are already known; the point is to test the reasoning. You don't need an account, and there's no leaderboard.

1 · Grid Dominion · Strategy

Can the second player force a tie?

Two players fill a 2×3 grid, one square per turn. Either player may choose red or blue. At the end, count horizontally and vertically adjacent pairs of each color. Player 2 wins if the two counts are equal.

Can Player 2 guarantee that result, whatever Player 1 does? Try a 3×3 board too. What changes?

2 · Blackboard Moves · Exact search

Can you beat nine moves?

Start with [4, 5, 5]. Each move chooses positive entries a ≥ b and replaces them with a+b and b−1. Stop when fewer than two positive entries remain.

Always choosing the two largest takes nine moves. Can you do better? What is the largest possible number of moves?

3 · Temporal Graphs · Proof

How many first-time winners?

Add one new undirected edge each day. An earlier edge's owner wins once its endpoints are connected by a path using only edges from later days.

When today's edge appears, could two owners become winners for the first time? The ladder preset is a good place to investigate.

4 · Number Forge · Number theory

Where does a residue shortcut break?

Build nonnegative integer combinations of 6, 7 and 10. Find the largest positive integer that cannot be built.

Then investigate a shortcut that uses only the smallest number of 7s matching the target's residue mod 2. It misses 14 and 21. Why?

Have a different answer?

I'd love to see an explicit move sequence, a shorter proof, or a reproducible case where the software disagrees with the mathematics. You can reply to the discussion where you found this challenge. For bugs, open a GitHub issue with the game, input and expected result.
